# 📜 Permanent Engineering & Living Documentation Standards

## 🌟 Universal Mandate: Documentation Integrity & Living Architecture Guides

For every project, codebase, and feature implemented by Antigravity, the assistant **MUST** adhere to the following standards:

---

### 1. Mandatory & Proactive Documentation Updates
- Primary documentation files (such as `BUILD_YOUR_OWN_AGENTIC_AI.md`, `EXTENDABLE_DESIGN_DOCUMENT.md`, `README.md`, `laymans_guide.md`, and project guides) are **critical, living artifacts**.
- Whenever a feature, tool, endpoint, UI view, or architectural subsystem is modified, added, or refactored, the documentation **MUST be updated immediately** in the same session without requiring user prompting.

---

### 2. The 5 Pillars of Every Feature Explanation
Every capability, tool, and system module documented **MUST** be explained using the following 5-part structure:

1. **What It Does (Plain English & Analogy)**:
   - Provide an intuitive, plain-English summary.
   - Always include a memorable, relatable real-world analogy (e.g., *"The Lego Builder for Workflows"*, *"The Airport Security Scanner"*, *"The Universal TV Remote Control"*).

2. **Why & How It Helps (Value Proposition)**:
   - Clearly explain the practical problem it solves.
   - Include a comparison table: **"The Challenge Before" vs. "How This Solves It"**.

3. **Real-World Simple Step-by-Step Scenario**:
   - Provide a concrete, relatable scenario with numbered step-by-step actions and expected outputs.

4. **Witty, Engaging & Humorous Commentary**:
   - Include lighthearted, relatable funny comments, witty footnotes, and realistic observations that make technical deep-dives engaging and approachable.

5. **Visual Flows & Under-the-Hood Code**:
   - Include clear Mermaid architecture diagrams (`flowchart LR`, `sequenceDiagram`).
   - Provide clean, tested code snippets with active file paths and API route signatures.

---

### 3. Production Portability & Zero-Dependency Graceful Fallbacks
- Always ensure new features include graceful offline/local fallbacks.
- Maintain test coverage for every newly added tool or endpoint.
